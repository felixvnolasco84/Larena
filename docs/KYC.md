## Workflow

Open `/admin/login`, verify an eight-digit email code (15-minute expiry), then use `/admin/kyc` to create invitations. All authorized staff have the same access. Copy the token link on creation; the token is not retained in plaintext. A new link replaces the old hash and renews the 30-day validity. Revocation is immediate.

The buyer can edit prefilled name, email and phone; project/unit/buyer classification belong to the invitation. Autosaves are serialized and checked against a backend revision. If a second device changed the draft, reload the saved version instead of silently overwriting it. Email confirmation must be reentered when reopening a draft. The last screen reviews the applicable answers before submission.

Files upload directly into Convex storage and are registered against a one-use grant with matching size/type metadata. UI format hints follow each Excel row: 10 MB normally, 25 MB for incorporation deed, power of attorney and shareholding structure. JPG/JPEG are equivalent. HEIC is restricted to the buyer ID field. Removing a draft attachment deletes that file; there is no bulk cleanup or retention job.

The final mutation validates applicable fields/files, allocates a sequential `KYC-LAR-` folio, snapshots consent, privacy URL, native notice version, form version and server signature date, and schedules two independently tracked emails. The original hidden IDs `kyc_id` and `firma_fecha` are retained alongside the server submission metadata. Repeating submission returns the same folio. Submitted data cannot be edited. Hidden answers and obsolete attachments are excluded from the final record; their storage is not automatically purged.

The UI downloads documents using a same-origin POST to `/api/kyc/files/[id]`. The Next.js server verifies a staff session or buyer capability, then streams the authorized file. Convex's resolver requires the private server proxy secret in addition to the caller's permissions. Storage URLs stay on the server and are never returned to the browser. Browser downloads may buffer up to 25 MB locally.

Resend receives T10/T11 for the buyer and T12 plus a private panel link internally. Documents are not attached. Transient errors retry up to three times, with idempotency keys and recovery jobs for interrupted actions. The panel allows manual retry after a final failure. Logs omit KYC content and credentials.

The panel filters before pagination, with indexed project/state filtering and full-text prefix search on unit/folio across all records. Results are delivered in batches of 20. PDF generation, Dropbox, SAT capture, automatic decisions, submitted-record reopening and automatic retention/deletion are outside this version.

## Verification

The 26 tests in `tests/kyc.test.ts`, `tests/kyc-ui.test.tsx`, `tests/kyc-mail.test.ts` and `tests/kyc-select.test.tsx` cover shared Excel rules, buyer variants, conditional fields, hidden answer removal, upload permissions, invitation rotation, indexed search, authorization, idempotent finalization, mail failures, bilingual drafts, network retries, mouse/touch signature events, proportional signature export at a narrow mobile width and both receipt languages. Select integration checks cover clearing filters, invitation FormData and translated countries retaining their ISO codes in autosaved answers. Internal T12 notifications always use Spanish, including their subject when the buyer submits in English. A signature remains on the canvas after a failed upload. `convex-test` omits file MIME metadata in its Blob mock, so tests explicitly supply the metadata that real HTTP uploads persist.

All KYC dropdowns use shadcn/ui's Radix Select through `components/Kyc/Select.tsx`: countries, language selectors, panel filters and invitation classification. The wrapper preserves the existing application values, including empty filters, while adapting the menu to Larena's colors, typography and radii. Rendered checks at 320, 390 and 1440 CSS pixels verified wrapping of long country names, bounded scrolling menus, visible keyboard focus and no page overflow. Keyboard checks covered opening, navigation to the last country, Escape and focus restoration. No menu animation was added.

Responsive verification covered every step at 320, 390, 768 and 1440 CSS pixels in Spanish, and at 390 pixels in English: 35 rendered checks without horizontal overflow. Twenty-one viewport screenshots cover the complete seven-step mobile flow with synthetic buyer, beneficial-owner, third-party payment and PEP information. Mobile actions use full-width controls, file uploads use accessible 48-pixel controls with visible keyboard focus, and file names/actions wrap independently. The canvas bitmap matches its displayed aspect ratio before drawing, so exported signatures retain their mobile proportions. No new animation was introduced.

Development integration QA verified direct storage uploads, signature image upload, a complete synthetic buyer submission and its receipt, protected streaming of an exact 25 MB PDF, and denial of cross-expedient file access. Browser checks covered bilingual state preservation, conditional beneficial-owner fields, required documents, review, keyboard focus and layouts at 390 and 1440 CSS pixels without horizontal overflow. Earlier synthetic visual QA records/files, temporary seed functions and the temporary privacy URL were removed after testing. On October 7, real OTP transport was verified in Gmail, as were four real notifications for the clearly labeled development cases `PRUEBA-RESEND-ES-0710` / `KYC-LAR-0002` and `PRUEBA-RESEND-EN-0710` / `KYC-LAR-0003`. Those two synthetic expedients remain in development for inspection; production has no buyer test records. Resubmission retained each folio and did not duplicate email. Authenticated staff download of the synthetic incorporation deed also succeeded. The panel uses Convex Auth's standard browser session storage and server cookies; KYC answers and invitation tokens are never stored in localStorage. Drawn touch signatures should be checked on an actual touch device before production.

The site's existing homepage includes remote photographs; in a network-restricted environment those images may fail independently of KYC. Production hosting access logs must redact `/kyc/[token]` and avoid request-body logging on KYC endpoints; this application does not log those values.
